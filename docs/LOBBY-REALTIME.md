# 로비 실시간 동기화 · 부하 테스트 정리

작성: 2026-09-14 · 대상: 로비(`app/_lobby/lobby.tsx`) ↔ 백엔드(`04_game_b` `src/lobby`)

## 한 줄 요약

로비는 HTTP 150ms 폴링에서 **WebSocket(`wss://api.ggpli.com/api/lobby/ws`)** 으로 바뀌었다. 서버 CPU는 동시 500명(분산)에서도 1코어의 약 22%로 여유가 있고, **남은 한계는 집 PC 업로드 대역폭**(업로드 100Mbps 기준 동시 약 300명)이다.

## 지금 구조

| 쪽 | 동작 |
| --- | --- |
| 프론트 (`app/_lobby/lobby.tsx`) | 상태(위치·방향·앉기·옷·때리기·채팅)가 바뀔 때만 50ms마다 전송, 가만히 있으면 2초마다 heartbeat. 끊기면 1→8초 간격으로 조용히 재연결("혼자 모드" 안내 없음) |
| 프론트 보간 (`lib/lobby/interpolation.ts`) | 받은 위치를 버퍼에 쌓고 100ms(`REMOTE_RENDER_DELAY_MS`) 과거를 이어 그린다. 같은 위치 중복은 무시, 1초 넘게 안 보인 유저만 지운다 |
| 백엔드 게이트웨이 (`src/lobby/lobby.gateway.ts`) | 50ms 틱마다 근처 플레이어를 보낸다. 지난번과 같으면 보내지 않는다. 연결당 초당 40개 초과 메시지·4KB 초과 본문은 버린다 |
| 틱 메시지 생성 (`src/lobby/presence.ts` `createViewer`) | 플레이어 JSON을 틱당 한 번만 만들고 `VIEW_RADIUS`(2000px) 격자 주변 9칸만 거리 계산. 좌표는 소수 첫째 자리 |
| 붐빔 모드 | 접속자 200명 초과 시 틱 100ms, 가까운 30명까지만 전송 (200명 이하는 50ms·60명) |
| 연결 확인 (`src/lobby/heartbeat.ts`) | 30초마다 ping, 다음 ping까지 응답 없으면 끊는다 (Cloudflare 터널 약 100초 유휴 끊김·좀비 연결 대비) |
| 압축 | 기본 끔. `LOBBY_WS_DEFLATE=1`로만 켠다 (아래 결과 참고) |
| 기존 HTTP | `POST /api/lobby`는 배포 전환 중 옛 클라이언트용으로 남아 있다 |

## 부하 테스트

`04_game_b`에서 실행한다. 서버를 이 프로세스에서 새로 띄우고 봇은 자식 프로세스로 붙여 **서버만의** CPU·메모리·틱 시간을 잰다. 운영 서버에는 붙이지 않는다(`NODE_ENV=test`라 Supabase로도 안 보냄).

```bash
cd ../04_game_b
pnpm load:lobby                                                   # 100/300/500명, 밀집(2500px, 70% 이동)
pnpm build && node scripts/lobby-load-test.ts --area 12000 --idle 0.6  # 분산(실제에 가까움)
node scripts/lobby-load-test.ts --deflate --json out.json          # 압축 켜고 비교, 결과 저장
```

측정 항목: 서버 CPU(1코어 기준)·RSS·heap, 틱 p50/p95/최대, 틱/초, 이벤트 루프 지연, 유저당 메시지/s·KB/s(JSON·실제 전송), 전체 송신량, 수신 간격, 한 봇의 움직임이 다른 봇에게 보이기까지 지연(p50/p95).

### 결과 (2026-09-14, 이 PC)

### 결론

- **CPU는 여유**: 현재 기본(붐빔 모드)으로 500명 분산 22%, 밀집 43%. 기준(1코어 50% 이하) 안
- **압축은 쓰지 않는다**: 대역폭은 16~25배 줄지만 300명부터 CPU가 1코어를 넘고 메모리가 컨테이너 한도(512MB)를 넘어 지연이 수 초가 된다
- **병목은 업로드 대역폭**: 분산 300명 ≈ 9MB/s(≈72Mbps), 500명 ≈ 19MB/s(≈150Mbps). 집 회선 업로드 100Mbps면 동시 약 300명 안팎이 한계
- 붐빔 모드에서는 수신 간격이 약 0.13~0.19초로 늘어 다른 유저 움직임이 살짝 덜 부드러울 수 있다 (200명 초과일 때만)
