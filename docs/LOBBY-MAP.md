`/`에서 카피바라를 방향키로 걸어 다니며, 맵 곳곳의 건물로 들어가면 게임이 시작되는 **걸어 다니는 게임 목록**.
INTENT.md의 "`/`는 나중에 게임 목록 페이지"를 걷는 방식으로 구현한다.

## 1. 목표 / 원칙

- 로비 자체가 목록 페이지다. 건물 = 게임 입구
- 게임 500개까지 늘어나도 맵 에셋이 게임 수만큼 늘지 않는다
- 에셋은 적게, 재사용 가능하게 (카피바라 걷기와 같은 원칙)
- 걷기를 싫어하는 사용자·검색엔진·스크린리더도 모든 게임에 바로 갈 수 있어야 한다
- 전체 화면 원칙(`h-dvh w-dvw`), 다크 테마 토큰, 광고는 로비 플레이 영역 밖

## 2. 시점과 화풍

- **시점:** 약간 위에서 내려다보는 3/4 탑다운. 이미 만든 카피바라 스프라이트가 이 각도라서 맞춘다
- **화풍:** 카피바라와 같은 털·점토 느낌 3D 미니어처 렌더, 부드러운 조명
- **테마(제안):** 카피바라 마을. 온천·귤나무·잔디·돌길. 테마는 확정 필요 (9번 참고)

## 3. 맵 구조

타일 + 소품 방식을 추천한다. 에셋 몇 장으로 맵을 계속 넓힐 수 있다.

| 레이어 | 내용 | 렌더 |
|---|---|---|
| 바닥 | 잔디·길·물 타일 몇 종을 격자로 배치 | 빌드 전에 파이썬으로 이어 붙여 **WebP 한 장**으로 구움 → DOM 1개 |
| 소품 | 나무, 바위, 울타리, 벤치 | 절대 위치 스프라이트 |
| 건물 | 게임 입구 (아래 4번) | 절대 위치 스프라이트 + 입구 좌표 |
| 캐릭터 | 카피바라 걷기 12장 (기존) | 지금 `app/page.tsx` 방식 그대로 |

- **맵 데이터:** `lib/lobby/map.ts`에 타일 격자(2차원 배열), 소품·건물 좌표를 한곳에 둔다. 에디터 도구는 만들지 않고 코드로 편집한다
- **크기:** 1단계는 40×30 타일(타일 64px → 2560×1920px) 정도
- **카메라:** 월드는 화면보다 크고, 카메라가 카피바라를 부드럽게 따라간다. 맵 끝에서는 카메라가 멈춘다. 이동은 기존과 같이 매 프레임 transform 직접 갱신
- **충돌:** 타일 격자에 "못 지나감" 표시(물·건물 몸체·나무 밑동). 발 위치 기준 박스로 검사하고, 벽에 부딪히면 벽을 따라 미끄러지게 한다 (x/y축 따로 검사)
- **앞뒤 가림:** 소품·건물·캐릭터를 발 위치(y) 순서로 `z-index` 정렬 → 나무 뒤로 걸어가면 가려진다
- **렌더 방식:** DOM + CSS transform으로 시작. 화면 안 소품이 수백 개가 넘어 느려질 때만 canvas로 바꾼다

## 4. 게임 입구 (500개 대응)

게임마다 건물 1채는 500개에서 불가능하다. 단계적으로 간다.

1. **지금 (게임 7개):** 게임마다 입구 1곳. 건물 모양은 3~4종을 재사용하고 간판(텍스트)만 다르게 한다
2. **게임 수십 개부터:** 건물 = **카테고리 오락실** (반응속도, 보드게임, 액션 …). 들어가면 그 카테고리 게임 목록 패널이 뜬다
3. **입구 연결:** `lib/games/registry.ts`의 `GameEntry`에 카테고리 필드를 추가하고, 맵의 건물은 카테고리를 가리킨다. 게임을 추가해도 맵은 안 고친다

**입장 방법**
- 입구 앞 영역에 들어가면 건물 위에 "Enter / Space로 입장" 말풍선을 띄운다
- Enter/Space, 또는 말풍선 탭으로 `/games/<slug>`로 이동한다. `<Link>`를 쓴다 (Cmd/Ctrl 클릭 지원)
- 게임에서 뒤로가기로 돌아오면 그 건물 앞에서 다시 시작한다 (위치를 `sessionStorage`에 저장)

## 5. 조작

- **키보드:** 방향키 + WASD, Enter/Space 입장, 8방향 이동 (기존 구현 재사용)
- **모바일:** 화면 아무 곳이나 누르고 끄는 가상 조이스틱 추천. 탭한 곳으로 걸어가기는 길찾기가 필요해서 나중에
- **바로가기:** 화면 구석에 "게임 목록" 버튼 → 게임 목록 패널 (걷기 싫은 사용자용)

## 6. 접근성 / SEO

- 맵은 시각 요소이고, 같은 게임 링크를 **실제 `<nav>` 링크 목록**으로 함께 렌더한다. 스크린리더와 검색엔진은 이걸 읽는다
- 현재 `/list`는 `noindex`이므로, 로비의 링크 목록이 사실상 게임 내부 링크 허브가 된다 (docs/SEO.md 9번과 연결)
- 동작 줄이기 설정 사용자: 카메라 부드러운 따라가기 끄기
- 첫 화면에 조작법 한 줄 ("방향키로 걷고 Enter로 입장")

## 7. 에셋 목록 (1단계)

모두 `scripts/make_image`로 생성하고, 기존 카피바라 이미지를 화풍 참고 이미지로 넣는다. 네이밍·폴더 규칙은 `scripts/make_image/skills.md`를 따른다.

| 종류 | 수량 | 생성 방법 |
|---|---|---|
| 바닥 타일 (잔디, 길, 물, 물가 가장자리) | 4~6장 | 한 장 시트로 한 번에 생성 → 자름 (색·조명 통일) |
| 소품 (나무, 바위, 울타리, 꽃) | 4~6장 | 한 장 시트로 한 번에 생성 → 자름 |
| 건물 (오락실 모양 3~4종) | 3~4장 | 시트 1장 |
| 입장 말풍선·그림자 | 0장 | CSS로 처리 |

총 생성 횟수 3~4번. 폴더: `public/assets/images/lobby/{tiles,props,buildings}/`

## 8. 진행 단계

1. **프로토타입 (에셋 없음):** 색 사각형 타일, 박스 건물로 월드·카메라·충돌·앞뒤 가림·입장까지 동작 확인. 기존 게임 7개 연결
2. **에셋 생성:** 타일·소품·건물 시트 생성 → 자르기 → 바닥 한 장으로 굽는 스크립트
3. **입장 흐름 다듬기:** 말풍선, 입장 전환, 돌아왔을 때 위치 복원, `<nav>` 링크 목록
4. **모바일:** 가상 조이스틱, 화면 크기별 카메라 확대 비율
5. **카테고리 오락실:** 게임 수가 늘면 registry 카테고리 필드 + 카테고리 패널

각 단계 끝에 실제 브라우저에서 걸어보며 확인한다.

## 9. 결정이 필요한 것

1. **맵 테마:** 카피바라 마을(온천·귤나무) / 오락실 거리 / 다른 제안
2. **입구 방식:** 지금은 게임당 입구 → 나중에 카테고리 오락실로 전환하는 계획이 괜찮은지
3. **모바일 조작:** 가상 조이스틱으로 갈지
4. **`/list` 유지 여부:** 로비의 링크 목록으로 대체하고 없앨지
