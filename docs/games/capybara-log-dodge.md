# 카피바라 통나무 피하기 — 기획 & 유저 모객 계획

slug: `capybara-log-dodge` · 경로: `/games/capybara-log-dodge` · 난이도: 보통 · LIST.md "장애물 피하기 (외길 러너)" 자리를 카피바라 테마로 채운다

## 1. 한 줄 요약

비탈 위에서 굴러 내려오는 통나무를, 온천을 향해 달리는 카피바라가 좌우로 피하고·점프로 넘고·숙여서 지나간다. **판 하나가 30초 안팎이라 "한 판만 더"가 쉽고, 기록을 링크 하나로 친구에게 들이밀 수 있는 게임**으로 만든다.

## 2. 핵심 게임 (최소 구성)

이미 있는 걷기 스프라이트 8방향을 그대로 달리기로 쓴다 (새 캐릭터 그림 없음).

| 항목 | 내용 | 재사용 |
|---|---|---|
| 시점 | 위에서 내려다봄. 카피바라는 화면 아래쪽에서 **위(`walk-up`)로 달린다**. 배경이 아래로 스크롤 | `lib/lobby/world.ts` 타일 그림체(진흙길·풀밭·갈대) |
| 조작 | 좌우: 화면 드래그 / ←→·A·D. 점프: 탭·위로 쓸기 / ↑·W·Space / 점프 버튼. 숙이기: 아래로 쓸기 / ↓·S / 숙이기 버튼(누르는 동안). 이동 중엔 `walk*-up-left/right`, 숙이기는 앉은 뒷모습(`capybara-idle-up`) | walk1/walk2 교대 = 달리기 (프레임 간격만 짧게) |
| 장애물 | 높이 3종 — 바닥(low, 점프로 넘음): ① 굴러오는 통나무 ② 화면 폭 전체 허들 / 머리 높이(high, 숙여서 지나감): ③ 화면 폭 전체 가로대(그림자 위에 띄워 그림) / 좌우로만(full): ④ 틈 하나 남긴 벽 ⑤ 튕기는 통나무 ⑥ 쪼개지는 큰 통나무 ⑦ 따라오는 통나무(420px까지 카피바라 쪽으로 휘어 오다 직진) — 0·4·8·12·18·24·30초에 차례로 해금, 22초부터 허들↔가로대 콤보 웨이브. 허들은 노란 ▲·바닥 띠, 가로대는 파란 밧줄·▼·진한 그림자로 구분하고 "점프!/숙여!" 안내·버튼·안내음(↑/↓)도 같은 색·방향 | 비행기 슈팅의 "붉은 경로 예고" 연출 |
| 속도 | 웨이브마다 느릿(0.65배)·보통·빠름(1.5배, 붉은 빛·속도선). 허들·가로대·쪼개지는 통나무는 늘 보통. 새 웨이브는 앞 통나무보다 0.35초(점프·숙이기가 끼면 0.7초) 늦게 닿도록 위에서 늦게 출발 | |
| 아이템 | 유자 수건(9초 뒤부터 12~18초마다): 먹으면 통나무 한 번을 막고 1.2초 무적. 아슬아슬이 2.5초 안에 이어지면 콤보(음이 한 음씩 올라감) | `wardrobe/hat/yuzu-towel.webp` |
| 소리 | 난이도 따라 112→172BPM로 빨라지는 달리기 비트, 빠름·느림 웨이브 소리, 보호막 획득·깨짐 | `playGameSound` 합성음 |
| 판정 | 히트박스는 그림보다 작게(관대하게). 한 번 맞으면 끝(체력 없음 = 짧은 판) | `capybara-stun.webp` 로 깔린 모습 |
| 공정성 | 좌우로만 피하는 통나무에는 **반드시 지나갈 틈**을 보장, 화면 폭 전체를 막는 건 점프·숙이기로 지나가는 통나무뿐. 가장 느린 허들도 체공 시간(0.56초)의 70% 안에 지나가 점프 타이밍 여유 보장 — `logic.ts`에서 검사하고 테스트로 고정 | 슈팅의 난이도 상한 방식 |
| 점수 | **버틴 시간(초, 소수 1자리)**. 숫자 하나라 공유·비교가 쉽다 | `tiers.ts` 등급 |
| 난이도 | 속도·밀도 제곱 곡선, 60초에서 최고치 후 유지 | 슈팅 `logic.ts` 곡선 |

화면 흐름은 CLAUDE.md 기록 게임 규칙 그대로: 시작 화면(순위표·공유) → 3·2·1 → 플레이 → 등급 결과 → 스크롤 시 순위표·광고.

## 3. 유저 모객 아이디어 (우선순위순)

판단 기준: **서버 없이 되는 것 먼저**, 사람이 사람을 데려오는 구조(공유·도전) > 혼자 오래 하는 구조(수집) > 실시간 멀티(비쌈).

### P0 — 첫 출시에 같이 넣는다 (서버 0, 비용 작음)

#### ① 도전장 링크 (가장 중요 — 바이럴 루프 본체)
- 결과 화면 공유 시 URL에 기록을 싣는다: `/games/capybara-log-dodge?vs=47.3`
- 링크로 들어온 사람은 시작 화면에 **"친구 기록 47.3초 — 이겨볼래?"**, 플레이 중엔 그 시간에 도달하는 순간 결승선 연출 + "친구 추월!"
- 결과 화면 공유 문구가 이기면 "47.3초 넘었다 😎 너도 해봐", 지면 "47.3초 못 넘음… 복수 도와줘"로 바뀜 → 받은 사람이 **다시 공유할 이유**가 생긴다
- 구현: `ShareButton`의 `text` + `window.location.href`에 `?vs=` 붙이기, `useSearchParams`로 읽기. `vs`는 숫자·범위 검사만(0~999). 서버 필요 없음
- SEO: `?vs=`는 canonical로 본 페이지 하나로 묶기 (`docs/SEO.md` 2번)

#### ② 오늘의 통나무 (매일 같은 코스)
- 날짜(KST)를 seed로 통나무 패턴을 결정 — 로비 맵이 seed 하나로 모두에게 같은 세상을 만드는 것과 같은 방식
- 같은 날엔 모두 같은 코스 → "오늘 코스 몇 초 버텼어?"가 **공정한 비교**가 되고, 내일은 새 코스라 **매일 올 이유**가 생긴다
- 시작 화면 토글: `오늘의 코스` / `연습(랜덤)`. 공유 문구에 "9월 14일 코스"를 넣어 날짜 기반 대화 유도
- 기록은 `local-records.ts`에 `courseDate` 필드 추가해 날짜별 최고기록 표시

#### ③ 웃긴 결과 등급 & 사망 멘트
- 등급 이름 자체를 공유하고 싶게: `통나무 밑 납작 카피바라` → `굴러다니는 카피바라` → `통나무 서퍼` → `산사태 속 평온` → `온천의 신`
- 사망 원인별 한 줄: "가로 통나무에 정면으로 박음", "3초 만에 납작" 등 (패턴 종류 × 시간 구간 조합, 문자열 배열로 충분)
- 등급별 결과 그림은 기존 이모티콘 시트 그림체로 5장

#### ④ 아슬아슬 연출 (영상으로 찍고 싶게)
- 통나무가 히트박스 몇 px 옆을 지나가면 "아슬아슬!" 텍스트 + 0.15초 슬로모션, 판 끝에 `아슬아슬 N번` 표시
- 세로(9:16) 화면 기준으로 점수를 크게 → 쇼츠·릴스·틱톡 녹화에 맞춤. `prefers-reduced-motion`이면 슬로모션 끔

#### ⑤ 즉시 재시작
- 결과 화면 어디든 탭 = 다시 시작 (광고는 스크롤 아래에만 있으니 실수 클릭 없음), 스페이스/엔터도 재시작
- 판 사이 대기 시간을 줄이는 게 곧 체류 시간·광고 노출

### P1 — 반응 보고 추가 (서버 0 또는 기존 서버 재사용)

#### ⑥ 로비 연결
- 오두막 아이콘: 나무 통나무 더미 소품 1장 (`assets-src/games/capybara-log-dodge/icon.png`). 로비 → 게임 유입은 자동
- 로비 통나무 의자(`log` 타일) 옆에 앉으면 "오늘의 통나무 도전하기" 말풍선 → 로비 체류 유저를 게임으로 보냄

#### ⑦ 카피바라 꾸미기 수집 (재방문)
- 누적 버틴 시간으로 모자 해금: 유자 → 귤 → 연잎 → 수건(온천) → 왕관. 저장은 localStorage
- 공유 링크에 모자를 실어(`&hat=2`) 받은 사람 화면의 "친구 카피바라"가 그 모자를 씀 → 자랑거리
- 비용은 그림 5장. 반응 없으면 안 만든다

#### ⑧ 친구와 동시 대결 (초대 코드)
- `rooms.ts`는 턴제(흑·백·턴 제한시간)라 실시간 달리기엔 안 맞는다. 대신 **같은 seed로 각자 달리고 끝나면 결과만 서버에 제출** → 둘 다 끝나면 승패 + 이모티콘 놀리기(`CAPYBARA_EMOTES`)
- 턴 대신 "둘 다 제출하면 끝" 규칙 하나만 `RoomRules`에 맞춰 넣으면 되는지 구현 시점에 확인. 안 맞으면 ①도전장 링크로 충분

### P2 — 보류 (필요성 확인 후)

- **전체 순위표·주간 랭킹**: 서버 저장소(DB)가 생긴 뒤. 지금 방/로비는 서버 메모리라 재배포 시 날아감. 조작 방지(기록 검증)도 같이 필요
- **로비 광장 실시간 생존전**: 여러 명이 같은 통나무를 동시에 피하기. WebSocket급 실시간이 필요 → 비용 대비 보류
- **카카오톡 SDK 공유**: 모바일 `navigator.share`가 이미 카톡 공유 시트를 띄움. OG 이미지 없이 썸네일이 밋밋하면 그때 검토

## 5. 성공 지표 (가볍게)

지금 분석 도구가 없으므로 출시 후 필요할 때 Vercel Analytics 커스텀 이벤트 3개만: `share_click`, `vs_link_open`(도전장으로 들어옴), `retry`(한 방문당 판 수). **`vs_link_open ÷ share_click`이 1에 가까워질수록 바이럴이 도는 것**.

## 6. 구현 순서 & 파일

```
app/games/_games/capybara-log-dodge/
  index.tsx                 # 레지스트리용 re-export
  capybara-log-dodge.tsx    # 화면·입력·렌더링 (canvas 또는 transform)
  logic.ts / logic.test.ts  # seed 패턴 생성, 틈 보장, 충돌, 난이도 곡선
  records.ts / tiers.ts     # local-records 재사용, 등급 5단계
lib/games/registry.ts       # 항목 1줄
assets-src/games/capybara-log-dodge/icon.png → public/.../icon.webp
```

1. `logic.ts` — seed 난수, 패턴 4종, "항상 틈이 있다" 테스트, 난이도 곡선 (P0 ②까지 포함)
2. 화면 — 시작/카운트다운/플레이/결과, 좌우 이동, 아슬아슬 판정 (P0 ③④⑤)
3. 도전장 링크 `?vs=` (P0 ①)
4. 레지스트리·LIST.md 체크·오두막 아이콘
5. 출시 → 1~2주 반응 보고 P1 착수 여부 결정
